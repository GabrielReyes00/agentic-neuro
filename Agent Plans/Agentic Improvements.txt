1. SYSTEM OVERVIEW
================================================================================

This repo is the backend for an AI-powered neurosurgery learning system.
It runs as a local CLI agent (Claude Code or Gemini CLI) that:
  - Retrieves information from 22 neurosurgery textbooks via vector search
  - Tracks the user's mastery of 265 ACGME curriculum topics via a knowledge graph
  - Writes structured study material to an Obsidian vault for visual review
  - Syncs Anki flashcards via the AnkiConnect API
  - Provides Socratic tutoring sessions, clinical simulations, and operative walkthroughs
  - Generates research reports with RAG-sourced citations
  - Manages inbox triage and calendar scheduling via MCP

Multi-agent: Claude Code (CLAUDE.md) and Gemini CLI (GEMINI.md) share the
same Python backend, databases, and Obsidian vault. Agent-specific behavior
is configured in their respective system instructions; all Python scripts are
agent-agnostic.

1b. KEY TECHNOLOGY CHOICES

  Vector DB:      LanceDB (local, columnar, fast)
  Embeddings:     BAAI/bge-m3 (1024-dim, multilingual, MPS-accelerated)
  Reranker:       cross-encoder/ms-marco-MiniLM-L-6-v2 (sigmoid scoring)
  NER:            SciSpacy en_ner_bc5cdr_md (medical entity extraction, optional)
  Knowledge DB:   SQLite via custom ORM in knowledge_graph.py
  Decay Model:    Stability-weighted Ebbinghaus: half_life = 48h * 2^(depth-1) * stability_factor
  Vault:          Obsidian with Dataview plugin (inline field queries)
  Anki:           AnkiConnect localhost:8765
  MCP:            Gmail, Google Calendar
  Agent:          Claude Code (Opus 4.6 primary) + Gemini CLI (Flash/Pro)

7a. LONG-TERM AGENTIC MEMORY SYSTEM (Iteration 7 — implemented 2026-04-13)
================================================================================

  OVERVIEW: Four architectural enhancements transform the episodic memory
  system from a passive log into an active retrieval engine with principled
  multi-stream fusion, token-efficient preflight, mid-session continuity, and
  temporal concept understanding tracking.

  --- THREE-TIER EPISODIC MEMORY ARCHITECTURE ---

  Episodic memories are stored in three complementary layers:

    Hot  (structured): SQLite `learning_exchanges` + `episode_summaries`.
         Per-exchange content: question, answer, correction, error_type,
         misconception, teaching_approach, outcome. Fast structured queries.
         Filter by topic, concept, error_type, skill, days_back.

    Warm (semantic):   LanceDB `episodic_memory` table (episodic_memory.lance/).
         BGE-M3 1024d embeddings of exchange text + episode summaries.
         Enables semantic recall ("find exchanges where Gabriel confused X
         with Y") that keyword search cannot do.

    Cold (narrative):  Obsidian vault Review Sessions/ files. Human-readable
         session logs written by learning skills at session end.

  --- RRF FUSION IN recall_episodes() ---

  recall_episodes() fuses three retrieval streams using Reciprocal Rank
  Fusion (k=60):

    Stream 1 (structured): SQLite filter by topic, error_type, skill, days_back
    Stream 2 (keyword):    LIKE matching on concept, question, answer fields
    Stream 3 (semantic):   LanceDB vector search on episodic_memory table

  RRF score = sum over streams of: 1 / (60 + rank_in_stream)
  Items appearing in multiple streams are boosted. Degrades gracefully when
  LanceDB is empty or query is absent (streams 1+2 only in those cases).

  Usage: python3 src/knowledge_graph.py recall "query" [--topic T] [--max N]

  --- PROGRESSIVE DISCLOSURE IN PREFLIGHT ---

  preflight.sh step 8 uses --compact mode. Compact output replaces verbatim
  question/answer/correction text with one-liner summaries + exchange_ids,
  reducing preflight JSON size by ~70-80% while preserving on-demand access
  to full content via exchange_history().

  preflight.sh       -> data/Sessions/episodic_memory.json (compact format)
  learner_context()  -> past_exchanges_compact key (exchange_id + one-liner)

  Full content on demand: python3 src/knowledge_graph.py exchange_history --concept "X"
  Explicit compact CLI: python3 src/knowledge_graph.py recall "query" --compact

  --- PRECOMPACT HOOK FOR MID-SESSION CONTINUITY ---

  src/precompact_memory_inject.py fires before Claude Code context compaction
  via PreCompact hook in .claude/settings.json. It queries learning_exchanges
  for the last 2 hours and outputs a compact memory block that gets injected
  into the compacted context:
    - Topics active this session + score summary
    - Key errors to re-test (concept, misconception, correction)
    - Teaching approaches used this session
    - Next-session strategy from most recent session_narratives row (Iter 8)
    - Recent concept evolution events — status transitions last 7 days (Iter 8)
    - Relevant prior session memory — SQLite only, last 30 days

  Non-blocking: always exits 0. Timeout: 60 seconds (Iter 8: was 15, raised for
  safety margin). SQLite-only queries — LanceDB NOT called from hook path.

  --- CONCEPT EVOLUTION VERSIONING ---

  concept_evolution table in knowledge_graph.db tracks concept understanding
  changes over time. Triggered automatically inside log_study_session() when
  concept_mastery.status changes.

  Each row records: previous and new status snapshot, trigger type
  (correct_recall, incorrect_recall, decay), FK to triggering exchange_id
  or signal_event_id, and a natural language evolution_note.

  Creates an audit trail: first misconception, correction, regression, final
  consolidation — all linked to the specific exchanges that caused each change.

  AGENTS: concept_evolution fires automatically from log_study. Do not call
  log_concept_evolution() manually.

  Query: python3 src/knowledge_graph.py concept_evolution --concept "X"

  --- TEACHING EFFECTIVENESS ANALYTICS ---

  teaching_effectiveness() aggregates outcomes by teaching approach per domain.
  Identifies which approaches (anatomical-tracing, Socratic, analogy, etc.)
  produce the best recall outcomes. Used by skills to adapt pedagogy.

  Query: python3 src/knowledge_graph.py teaching_effectiveness [--domain D]
