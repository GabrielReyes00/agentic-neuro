EXECUTIVE SUMMARY
================================================================================

The agentic-neuro repository has accumulated significant technical debt through
multiple architecture redesigns. The codebase is at a functional plateau where
obsolete memory logging paths, redundant skill files, unused knowledge graph
commands, stale database backups, and scaffolding code remain side-by-side with
modern implementations.

Key findings:
- ~50 knowledge_graph.py CLI subcommands, several unreferenced
- Duplicate skill files (.claude/commands/ vs .gemini/commands/) with drift
- Obsolete logging scaffolds (log_turn.sh, log_event, log_study still wired in
  some skills) superseded by memory_orchestrator.py record-answer
- Stale temporary artifacts in data/Sessions/ (concept_maps from April 8-10)
- One unused database backup (knowledge_graph.db.pre_stability_backup)
- Dead script files (generate_full_study_doc.py is a one-off, never imported)
- Redundant vault writers (vault_kg_sync + vault_canvas_builder both called from
  post-session hook with no deconfliction)
- Single unreferenced KG command (backfill_specificity)

PHASE 4 — SKILL DUPLICATION: .claude/commands/ vs .gemini/commands/
================================================================================

14 skill files exist in both directories. Gemini variants are 40-60% longer
than Claude variants — they have drifted independently:
- .claude/commands/ total ≈ 1996 lines
- .gemini/commands/ ≈ 3526 lines
- Same backend (memory_orchestrator.py, knowledge_graph.py) but divergent
  prose, sequencing, and bug-fix history.

Recommendation:
1. Promote .claude/commands/*.md as the canonical spec.
2. Keep .gemini/commands/*.md only for genuinely Gemini-specific deltas
   (sequential vs parallel tool execution, TOML hook plumbing).
3. Move shared protocol blocks (e.g., §7e Universal Learning Signal Protocol
   verbatim) into a SKILL_REFERENCE.md and have both sides reference it.
4. Add a CI check: any divergence in shared sections >10% triggers a warning.

Safety: Skills are user-facing. Make changes per-skill, run each skill
end-to-end after consolidation, never bulk-rewrite.

================================================================================
PHASE 5 — HOOK / HEARTBEAT / PREFLIGHT OVERLAP
================================================================================

preflight.sh, heartbeat.sh, universal_post_session_hook.py, and
precompact_memory_inject.py overlap in responsibilities:

- apply_decay runs in BOTH preflight and heartbeat (and post-session hook).
- preflight + heartbeat both call log_doc_progress style commands with
  slightly different parameter formats.
- post-session hook re-runs many of the same dashboard/gaps/review_queue
  queries that heartbeat already executed during the session.

Recommendation:
- Decide: apply_decay runs ONCE per session, at session start only (in
  preflight). Strip from heartbeat and post-session-hook.
- Document the lifecycle in CLAUDE.md as an explicit state diagram:
  preflight → [active session loop with heartbeat checkpoints] → post-session-hook
- Unify --topics argument format across both shell scripts.

Safety: Edit one hook at a time. After each change run a full /study-session
end-to-end and verify Dashboard.md, ACGME Readiness.md, and a Concept file
all update correctly.

================================================================================
PHASE 6 — VAULT WRITER DECONFLICTION
================================================================================

src/vault_kg_sync.py (982 lines) and src/vault_canvas_builder.py (540 lines)
are both invoked from src/universal_post_session_hook.py independently:

- No transactional wrapper. If vault_kg_sync succeeds and vault_canvas_builder
  fails, vault is left in a half-updated state.
- Both contain near-duplicate logic for loading the curriculum/ACGME milestone
  index.
- No locking — concurrent sessions could clobber Concepts/*.md.

Recommendation:
- Extract the shared curriculum-index loader to a small util module
  (src/vault_common.py).
- Wrap both calls in a VaultOrchestrator in the post-session hook that logs
  all writes and rolls back on failure (or at minimum surfaces the
  inconsistency).
- The three protected Concepts files (per §4) should be enforced in the
  orchestrator, not in each writer separately.

Safety: Run a dry-run mode that prints planned writes first. Verify with
git diff in the vault that no protected file gets touched.

that's an architectural smell, not just bloat.

Safety: SQLite column drops require table rebuild. Always backup, run inside
a single transaction, and re-run test_memory_architecture.py after.
